# Чат в выводе агента

Вкладка «Чат» открывается по умолчанию в окне «Вывод агента». Это история работы
над выбранной задачей: отправлять сообщения из этого окна пока нельзя.

Новые сообщения агента о ходе выполнения и итоговый отчёт используют язык интерфейса,
выбранный при запуске или продолжении задачи. Смена языка во время выполнения влияет
на следующий запуск/продолжение. Автоматическая очередь сохраняет язык её запуска.
Прежние сообщения и исходный вывод инструментов не переводятся.

Лента оформлена как переписка: исходная задача показана справа, ответы агента —
слева, с аватаром и временем сообщения. Инструменты и размышления занимают компактные
строки между ответами; параметры и результаты раскрываются по нажатию. Содержимое
ограничено удобной для чтения шириной, прокрутка работает внутри чата, в том числе
на мобильном экране.

Сообщения агента отображаются с Markdown. Размышления, которые провайдер передал
в блоках `thinking`, и вызовы инструментов свёрнуты. Карточка инструмента показывает
его название и состояние; внутри доступны входные параметры и полученный результат.
Отсутствующий результат не считается успешным выполнением. Новый запуск, продолжение
или этап pipeline отмечается границей сеанса. Окно остаётся открытым после завершения.

При просмотре предыдущих сообщений новые записи не меняют положение прокрутки.
Кнопка «Новые сообщения» возвращает к концу истории. Доступны также вкладки итогового
отчёта, изменений Git и исходного текстового вывода.

## Хранение и доставка

Исполнитель сохраняет события в
`.automaker/features/<featureId>/agent-conversation.jsonl`. Записи добавляются
последовательно и имеют идентификатор запуска, порядковый номер и время. Запись
на диск предшествует отправке `auto_mode_conversation` через существующий канал
`auto-mode:event`. Запись использует тот же механизм владения запуском, что и
остальные изменения задачи: устаревший запуск не может дописать историю нового.

`POST /api/features/agent-output` возвращает прежнее поле `content` и массив
`conversation`. UI объединяет снимок с событиями по ID, проверяет и путь проекта,
и ID задачи. Периодическая загрузка и повторное подключение восстанавливают события,
пропущенные при отключении. Незавершённая строка после аварийного завершения процесса
не мешает читать остальные записи и продолжать историю.

В историю попадают нормализованные сообщения провайдера во всех потоках исполнителя:
планирование, выполнение подзадач и продолжение после согласования плана. Внутренние
системные промпты не сохраняются как сообщения пользователя. Размышления не вычисляются
и не реконструируются: провайдер может их не предоставлять.

Старые задачи также отображаются как переписка: клиент выделяет сообщения и маркеры
инструментов из сохранённого `agent-output.md`, сохраняя текст и примеры кода.
При первом продолжении прежний текст переносится в историю предыдущего вывода.
Время старых сообщений не выдумывается; результат инструмента не считается успешным,
если старый формат его не сохранил. Данные,
которые раньше не сохранялись, в том числе пропущенные размышления, восстановить нельзя.

Сохранённая секция `Tool results` разбирается как результаты инструментов, а не как
ответ агента. Для старых записей, в которых у вызова отсутствует ID, результат
привязывается по имени только при единственной паре в пределах сеанса. Если несколько
одноимённых вызовов нельзя однозначно сопоставить, результаты остаются отдельными
строками инструментов. Новая структурированная история связывает их по ID вызова.

Для использования новой истории нужно обновить backend и UI. Если обновлён только UI,
он продолжит отображать прежний текстовый вывод.
